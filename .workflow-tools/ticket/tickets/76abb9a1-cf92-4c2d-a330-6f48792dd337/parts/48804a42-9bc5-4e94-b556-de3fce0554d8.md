## Required finding and autofix examples

- Missing target: blocking `missing_target`, source line and normalized target included, no autofix proposed unless a unique safe replacement exists.
- Guidance target: non-blocking valid closure edge with resolved repository-relative path.
- Ticket/spec/code target: blocking `non_guidance_target` with detected class and instruction to remove or explicitly transform the reference.
- Ordinary repository Markdown outside guidance: blocking portability target unless policy marks the path as permitted metadata.
- Nested repository/submodule target: classified with source and target repository roots; never silently reported as a missing file.
- External URL and fragment-only link: skipped/non-blocking with explicit skip reason and no autofix.
- Unsupported scheme or dependency kind: blocking `unsupported_dependency` with the raw destination and supported alternatives.
- Traversal or symlink escape: blocking `unsafe_path`; autofix refuses automatically.
- Safe registered relocation: autofix plan shows old destination, new destination, source hash, diff, and post-audit expectation; apply requires explicit opt-in.
- Stale finding: changed source hash causes autofix refusal and asks for a fresh audit instead of overwriting new content.
