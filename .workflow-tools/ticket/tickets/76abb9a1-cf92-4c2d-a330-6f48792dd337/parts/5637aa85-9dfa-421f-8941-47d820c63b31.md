## Acceptance criteria

AC1. The audit exposes stable machine-readable classes for missing target, valid guidance target, non-guidance target, cross-repository target, external URL, fragment-only link, unsupported dependency, unsafe path, and unreadable artifact.

AC2. A local relative link from guidance to an existing ticket, specification, code file, generated file, or unrelated non-guidance Markdown file is reported as a blocking finding with source/line/raw destination/resolved target/classification/remediation.

AC3. Existing valid guidance links remain non-blocking; external URLs, mailto/data destinations, and fragment-only links retain documented skip behavior; percent-encoded and Windows-style paths resolve consistently.

AC4. Nested repositories and submodules are classified with both source and target repository identities. The result is never silently collapsed into `missing_target` or silently accepted as portable.

AC5. `audit links <root>` and full audit return non-zero when any blocking portability or missing-target finding exists, and their human/JSON outputs contain the same stable finding identity and evidence.

AC6. The hard-blocking pre-commit hook rejects a staged guidance file containing a blocking portability finding, names the source and target, and succeeds after the finding is repaired. `--no-verify` remains the documented explicit bypass.

AC7. Normal guidance installation consumes findings in detection-only mode: a blocking report prevents writes and a clean report is required before installation proceeds.

AC8. `guidance autofix --plan` is read-only; `guidance autofix --apply` is the only mutation path, requires explicit scope/confirmation, and refuses unsafe, ambiguous, unsupported, stale-hash, or non-guidance transformations.

AC9. A successful autofix applies only registered safe transformations atomically, records before/after content or link data, reruns the audit, and exits non-zero with rollback evidence when the post-audit still has blocking findings.

AC10. Focused tests cover every finding class, hook exit behavior, JSON/human parity, no-write defaults, stale hashes, safe apply, rollback, and post-fix audit failures.
