## Validation contract

### Audit validation

1. `cargo test -p audit-api markdown_links` must pass parser, classification, path, nested-repository, and finding-serialization tests.
2. `cargo test -p audit-cli links` must pass CLI exit-code and human/JSON rendering tests.
3. Run `audit links <fixture-root>` for a clean fixture and assert exit 0, zero blocking findings, and expected skipped URL/fragment counts.
4. Run each blocking fixture and assert exit non-zero, exact stable category/id, source line, raw destination, resolved path, and remediation text.
5. Run the staged-hook fixture and assert broken/misclassified guidance commits are rejected while repaired commits pass.

### Autofix validation

6. `cargo run -p install-ctl -- guidance autofix --help` must expose plan/apply, finding/report input, scope, and explicit confirmation controls.
7. `guidance autofix --plan` must leave source and destination hashes unchanged and emit a deterministic plan.
8. Apply a safe relocation fixture with an expected diff, verify the source hash precondition, atomic result, post-audit pass, and recorded evidence.
9. Change the source after plan generation and assert stale-hash rejection with zero write.
10. Trigger ambiguous, unsafe, unsupported, and non-guidance findings and assert refusal; trigger post-audit failure and assert rollback/non-zero result.

### Evidence and exit criteria

- Record validation specs and executions linked to ticket `76abb9a1-cf92-4c2d-a330-6f48792dd337`.
- Preserve representative JSON reports, autofix plans, diffs, and post-audit results under the fixture scope.
- AC1-AC10 each have command-backed evidence; no test claims success from human output alone.
